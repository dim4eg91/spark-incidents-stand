# Если стенд не работает

Начни с наблюдаемого симптома. Все команды ниже выполняются в PowerShell 7
из каталога с `compose.yaml`. Сохраняй полный текст ошибки: последние строки
иногда показывают только следствие. Удаление контейнеров, volumes и переустановка
Docker не входят в первый диагностический шаг.

## Jupyter не открывается

Открой [http://localhost:18888/lab](http://localhost:18888/lab).
Это адрес при стандартной настройке. Узнать фактически опубликованный порт:

```powershell
docker compose ps spark-incidents-jupyter
docker compose port spark-incidents-jupyter 8888
```

Ожидаемый вывод второй команды: `127.0.0.1:18888`.
Число `8888` здесь является внутренним портом. Адрес из лога
`http://spark-incidents-jupyter:8888` предназначен для контейнерной сети.
На Windows открывай опубликованный порт `18888`.

Docker Desktop может показывать сначала `14040:4040` и `14041:4041`.
Эти ссылки ведут в Spark UI. Для Jupyter нажми `Show all ports` и найди
`18888:8888`. Если Spark-приложение не запущено, порт `14040` может вообще
не отвечать, хотя Jupyter исправно работает.

Если браузер сообщает `connection refused`, проверь состояние контейнера и
логи. Если контейнер healthy, проверь ответ с Windows:

```powershell
docker compose logs --tail 80 spark-incidents-jupyter
curl.exe --noproxy "*" -I http://127.0.0.1:18888/login
```

При изменённом опубликованном порте подставь его. HTTP 200 подтверждает
доступность страницы входа, но ещё не работу notebook. HTTP 302 при открытии
`/` или `/lab` без авторизации обычно означает переход на страницу входа.
Если `127.0.0.1` работает, а `localhost` нет, проверь настройки локального
адреса и исключения proxy. Не отключай антивирус или firewall целиком.

## Страница входа открылась, но войти не получается

В верхнее поле `Password or token` вставь значение `JUPYTER_TOKEN` из `.env`
и нажми `Log in`. Нужна только часть после `=`, без пробелов по краям.
В учебной поставке это `sparkstudent`. Если `.env` не создан и переменная
не переопределена в окружении PowerShell, Compose использует это значение
по умолчанию. Нижняя форма установки нового пароля для курса не требуется.

Если менял токен в `.env`, обычный `restart` не обновит окружение контейнера.
Сначала сохрани открытые notebook, останови SparkSession и kernel, затем:

```powershell
docker compose up -d --no-deps spark-incidents-jupyter
```

После применения конфигурации открой страницу заново. Если вход всё ещё
отклоняется, проверь, не переопределена ли `JUPYTER_TOKEN` в текущем PowerShell.
Вывод `docker compose config` содержит секреты, его нельзя отправлять целиком.
Не выключай аутентификацию ради проверки. При повторных перенаправлениях
попробуй приватное окно и проверь, разрешены ли cookies для локального адреса.

## Видна страница, но рабочий интерфейс пустой

Дождись окончания загрузки и обнови страницу. Проверь в приватном окне,
чтобы отделить кеш и расширения браузера от серверной ошибки. Сохрани URL
без `token`, статус контейнера и новые строки лога после обновления.

В старой сборке встречалось `unexpected keyword argument 'proxies'`.
JupyterLab 4.2.5 пытался создать менеджер установки расширений с аргументом,
который удалён в httpx 0.28.1. Сервер переходил к read-only менеджеру и
продолжал запуск. По этой ошибке нельзя заключить, что веб-сервер остановлен.

В текущем Dockerfile заранее задан `--LabApp.extension_manager=readonly`.
Установка расширений через интерфейс отключена, notebook и kernel работают.
Если у тебя старая сборка, после сохранения работ и завершения kernel выполни:

```powershell
docker compose up -d --build --no-deps spark-incidents-jupyter
```

Это пересоздаёт Jupyter; файлы в `workspace` сохраняются. Установка случайной
версии через `pip install` внутри работающего контейнера нарушит повторяемость
и пропадёт при пересоздании. Обновления окружения делает автор в поставке.

## Docker, сборка и порты

Если `docker version` показывает только Client, проверь готовность Engine
и Linux containers по [windows-setup.md](windows-setup.md). При `WSL needs updating`
используй маршрут обновления WSL из этого справочника.

При ошибке скачивания образа, пакета или JAR запиши URL и текст ошибки.
Проверь сеть, корпоративный proxy и доступ к указанному registry. Ошибка TLS
не является основанием отключать проверку сертификатов. Если доступ регулирует
организация, обратись к администратору. После восстановления сети повтори start.

При `port is already allocated` посмотри `docker ps` и найди занятый порт.
Не останавливай контейнеры другого проекта. Можно изменить внешний порт
в `.env` и повторить start. Например, для Jupyter меняется `JUPYTER_PORT`;
внутренний порт `8888` и hostname остаются прежними. Пользуйся новым адресом
из вывода запуска. Диапазон Driver UI должен сохранять число портов: 11.

Для `unhealthy`, `exited` или `restarting` собери:

```powershell
docker compose ps -a
docker compose logs --tail 80 spark-incidents-jupyter
docker compose logs --tail 80 spark-incidents-master
docker compose logs --tail 80 spark-incidents-worker-1
docker compose logs --tail 80 spark-incidents-worker-2
```

В профиле storage контейнер `spark-incidents-minio-init` является одноразовым.
Его `Exited (0)` ожидаем после успешной загрузки исходников. Ненулевой код
требует проверки его лога; перезапускать его постоянно не нужно.

## Notebook или CSV не найдены

Jupyter показывает `workspace`, поэтому исходный CSV из `data` не обязан
быть виден в левой панели. В коде используй
`/data/csv/intro/orders_intro.csv`. Путь `D:\...` принадлежит Windows.
При отсутствующем notebook пройди [files-and-notebooks.md](files-and-notebooks.md).

Если используешь локальный Python или другой Jupyter из VS Code, контейнерные
пути там могут отсутствовать. Для первого запуска открой Jupyter этого стенда
в браузере. В kernel проверь:

```python
import os
import sys
from pathlib import Path
print(sys.executable)
print(os.environ.get("SPARK_MASTER_URL"))
print(Path("/data/csv/intro/orders_intro.csv").is_file())
```

Ожидаются Python внутри Linux, `spark://spark-incidents-master:7077` и `True`.
В 1.2 те же предпосылки проверяет учебный notebook.

## Spark долго ждёт или UI пропал

У стенда два вычислительных core. Другая активная SparkSession может занять
оба. На Master UI проверь приложения; в Jupyter открой Running. Сохрани
нужные работы и заверши лишнюю сессию штатно. Затем повтори опыт.

Driver UI живёт вместе с приложением. После `spark.stop()` закрытый порт
ожидаем. При следующем приложении адрес снова печатается в notebook.
Включённый History Server показывает завершённые приложения с event log.
Наличие двух Worker ещё не доказывает два Executor именно твоего приложения:
смотри вкладку Executors его Driver UI.

## MinIO и повторная проверка

MinIO нужен только начиная с опытов S3. Запусти `start.ps1 -Profile storage`.
Console по умолчанию находится на `http://localhost:19001`, API на `19000`.
В Spark endpoint другой: `http://spark-incidents-minio:9000`.
Логин и пароль смотри в `.env`. JAR лежат в образе в `/opt/spark/jars`.
Инструкции DE-практикума про ручной каталог `/jars` сюда не подходят.

После исправления запусти `health.ps1 -Profile core` либо `-Profile all`,
если включил все профили. Успех подтверждает итоговый `SMOKE_JSON`.
Не удаляй volumes ради ошибки входа или пути: там могут храниться данные MinIO
и история. Обычная остановка `stop.ps1` их сохраняет.

## Что приложить к обращению

Укажи урок и шаг, команду или URL без токена, ожидаемый результат и фактическую
ошибку. Добавь версию Windows, PowerShell, Client/Server Docker, `compose ps -a`
и последние строки нужного сервиса. На скриншоте оставь адрес без секрета,
текст ошибки и название вкладки. Убери `.env`, пароли, токены и личные пути.

Технические источники: [режим расширений JupyterLab 4.2](https://jupyterlab.readthedocs.io/en/4.2.x/user/extensions.html#configuring-the-extension-manager),
[удаление proxies в httpx 0.28](https://github.com/encode/httpx/releases/tag/0.28.0).
Инструкции сверены с локальным стендом 22 сентября 2026 года.
