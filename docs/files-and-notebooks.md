# Файлы стенда и notebook из уроков

В курсе два комплекта файлов. Стенд содержит Docker-конфигурацию, программы
запуска и учебные CSV. Notebook ты скачиваешь отдельно из вложений урока.
Успешный запуск контейнеров сам по себе не добавляет уроки в Jupyter.

## Получение стенда с GitHub

В уроке 1.2 на Stepik дана ссылка на публичный репозиторий и конкретный выпуск
стенда. Открой выпуск на GitHub, скачай `Source code (zip)` и нажми
«Извлечь всё». Git и аккаунт GitHub для курса не нужны. Не запускай команды
внутри открытого архива. В извлечённой папке найди `compose.yaml`; если
удобно, переименуй эту папку в `spark_incidents_stand`.

Не распаковывай новый выпуск поверх своих работ без резервной копии. Перед
обновлением сохрани `workspace` и `.env`, прочитай заметки к выпуску. Не смешивай
файлы двух версий стенда в одной папке.

## Где хранить файлы

| Каталог или файл | Для чего он нужен |
|---|---|
| `compose.yaml`, `docker`, `config` | Запуск окружения; меняй только по инструкции |
| `.env` | Твои локальные порты и токен; не публикуй |
| `data/csv` | Зафиксированные учебные данные; сохраняй исходники |
| `workspace` | Твои notebook, их копии и результаты |
| `workspace/output` | Результаты опытов, по отдельной папке на лабораторную |
| `docs` | Установка, работа с файлами, диагностика |

## Открой notebook 1.2

На шаге 4 урока скачай вложение `01_02_environment_check.ipynb`.
Если вложения нет, это проблема комплектации урока: сообщи автору номер урока
и шага. Создание пустого notebook не заменит учебный файл.

В Проводнике включи отображение расширений файлов. Проверь, что получил
`.ipynb`, а не `.ipynb.txt` и не HTML-страницу скачивания. Перенеси файл
в `workspace` внутри своего каталога стенда. Например:

```text
D:\spark-course\spark_incidents_stand\workspace\01_02_environment_check.ipynb
```

Открой [JupyterLab](http://localhost:18888/lab), войди с токеном из `.env`.
В левой файловой панели нажми Refresh, если файл ещё не появился, затем
открой его двойным щелчком. В заголовке документа проверь имя файла.
Если Jupyter предложит kernel, выбери `Python 3 (ipykernel)`.

Файловая панель Jupyter уже показывает содержимое `workspace`. Входить
в ещё одну папку с таким именем не нужно. Внутренний путь здесь
`/home/jovyan/work`. Альтернативный способ загрузки: кнопка Upload Files
в этой панели. Загрузи тот же `.ipynb` в её корень; файл окажется в `workspace`
на Windows. Выбери один способ, чтобы не создавать случайные дубликаты.

## Выполнение и сохранение

Читай пояснения и выполняй code-ячейки сверху вниз через Shift+Enter.
В 1.2 начни с одной строки `print(2 + 2)`: получи 4, замени второе число
на 3, повтори запуск и получи 5. Сохрани файл. Затем выполни готовую
проверку CSV без дописывания кода: она должна напечатать `ENVIRONMENT CHECK: OK`.
Этот notebook не создаёт SparkSession. В 1.3 ты отдельно разберёшь
состояние переменных, перезапуск kernel и повторный прогон.

Нажимай Ctrl+S после изменений. Файл сохраняется в `workspace` на Windows.
Закрытие вкладки браузера не гарантирует остановку kernel. Завершай нужный
kernel через панель Running. В уроках со Spark перед этим выполняй `spark.stop()`.

Не редактируй исходный CSV ради прохождения проверки. Для собственных опытов
сделай отдельную копию в `workspace`. Сохраняй резервную копию своих notebook
за пределами каталога стенда: bind mount обеспечивает доступ к файлу, но не
защищает от случайного удаления этого файла на Windows.
